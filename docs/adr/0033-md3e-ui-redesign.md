# ADR-0033 UI 走 Material 3 Expressive 重设计：新增可切换的 md3e 界面形态，旧版整套保留

状态：接受（2026-10-15）
决策人：HibernalGlow（用户 2026-10-15 口径：整体按 MD3 Expressive 重设计，原 UI 作为另一套保留）
相关：**ADR-0006（UI 真源是 Xiranite，搬运不发明）——本条是对它"视觉面"的一处受使用者授权的收窄例外，不改它对逻辑面的约束**、
ADR-0008（L2 共享与 L4 边界）、ADR-0010（品牌自称 Xaihi）、ADR-0011（降级铁律）、
ADR-0013（配置只走 DSH 标准面）、`DESIGN.md`（MD3E 设计契约）、`docs/adr/0007-component-placement.md`

## 背景

使用者要求把整个项目的 UI 按 **Material 3 Expressive（MD3E）** 重做——工作台、每个节点、顶栏、设置全部重设计，
并优化响应式；同时**保留原本那套 UI 作为另一套存在**，操作逻辑不变。参考基准是 `cromaguy/Rhythm`
（使用者原话："它是我见过 MD3 Expressive 做得比较好的一个项目，而且它已经有了随机图形"）。

这件事和 ADR-0006 正面相关，必须先说清楚边界，否则下一个 agent 会拿"搬运不发明"把这次重设计判成违规，
或者反过来拿这次授权去重写本该搬运的业务逻辑。ADR-0006 的原文判据是"**保真不是好看**"、
"`md3` 只是六套语言里的一套，**不是默认值**"（`packages/ui-host/src/lib/design-theme/contract.ts:28` 的
`AppDesignThemeId`，默认 `id: "native"` 见 `contract.ts:314-362`）。本条**不推翻**这些约束里属于"逻辑面"的部分：
节点的业务核心、动作、参数语义、CLI/TUI 面、以及配置通路仍然照 ADR-0006 / ADR-0013 搬运与接线。
本条只把**视觉面**划出来，作为使用者点名的一次重设计。

还有一条现状必须先记账：`but status`（2026-10-15 实测）显示**一大批 MD3/设计语言/设置文件正在别的 lane 里改**——
`DESIGN.md` 本身是 lane `rmo` 尚未提交的新增（`A`），`contract.ts`、`md3/resolve.ts`、
`settings/DesignThemeSection.tsx`、`settings/ThemeSettings.tsx`、`styles/design/md3-*.css` 全是 `M`，
同时 `nodes/encodeb`、`nodes/linku`、`nodes/smartzip` 正在被删（`D`）。
**所以：本 ADR 不改这些在飞文件；节点清单以运行时注册表为准，不写死数量。** 交付的两条构建提示词必须把"先与在飞 lane 对账"作为第一步。

## 需求（本会话逐条与使用者敲定）

1. **旧版整套保留，新版是另一套可切换的界面形态。** 切回旧版恢复的是**完整旧版**（原布局 + 原节点 + 原顶栏 + 原设置 + 原六套设计语言），
   不是只保留旧配色。新版是**专用 MD3E 形态**，与旧版并列，**不擅改出厂默认**（默认仍是现状的 `native`，
   用户口径"可以切换"）。这与 ADR-0006"不把某个候选提成默认"一致。
2. **操作逻辑不变，布局可重做。** 动作含义、快捷键、手势、输入输出、危险确认（如 `TopBar.tsx:176-202` 的 Hazard 上膛）
   一个都不改；但控件的**位置、分区、分组、窄尺寸下的呈现方式**允许重排。
3. **设置彻底重构，按目的分类。** 现状是 `ThemeSettings.tsx:32-38` 的五段（外观/工作区/视图/运行时/数据）。
   新版按使用者要解决的四个痛点重做：**分类与查找、布局与操作密度、外观与效果预览、层级与生效范围**。
4. **"随机图形"指的是真实可交互控件（尤其按钮）的形态**，不是节点图标背景、不是整张卡片轮廓
   （使用者两次纠正）。按**控件类型适配**：图标按钮可取花瓣/多边形等表达性形状；文字按钮保留适合文字的形态
   （胶囊/圆角）；开关、滑杆等各自按 MD3E 规范重做。**同一节点内同类按钮形状一致。**
5. **固定 / 随机在每个节点自己的设置入口里独立设置，保存到该节点的插件配置**，不影响别的节点
   （使用者原话："每个节点不是已经有自己的节点设置了吗……可以保存到自己的插件配置中"）。
   随机时机 = **应用启动时随机、使用中稳定**：重排、切视图、组件卸载重建都不重抽；可把当前组合"固定"下来。
6. **保留自由切换配色与配色风格。** MD3E 的**造型/布局/交互**与**颜色策略**解耦：换配色、换配色风格、换明暗
   都不会把界面打回传统 MD3，也不会锁定成参考原型的紫色。取色引擎已在（`@material/material-color-utilities@0.4.0`，
   9 个 scheme variant + 4 档对比度，`contract.ts:49-68`，默认 `variant: "expressive"` 见 `contract.ts:323`）。
7. **顶栏按 MD3E 重设计，操作逻辑不变。** 现状 `TopBar.tsx:66` 起（品牌/工作区入口 `:159-172`、视图切换 `:204-208`、
   窗口控制 `:99-129`）保留全部动作语义，只重做视觉与分区。
8. **优化响应式。** 复用既有的**按容器**（非按视口）分档：`useNodeSurface` 的
   `collapsed|compact|portrait|regular|expanded|workspace` 六档 + `tight|normal|roomy` 三密度
   （`packages/ui-host/src/nodes/shared/useNodeSurface.ts:14-29`）。设置页已按同一批阈值调 chrome 密度
   （`ThemeSettings.tsx:41-88`）。

## 决定

1. **新增一个"界面形态（UI face）"维度：`legacy | md3e`，与"设计语言"正交。** 旧形态完整保留（含六套设计语言）；
   新形态是整套 MD3E 界面。二者共享同一份 store、同一批动作、同一套节点契约，**只切视觉面，不复制业务**。
   切换入口在设置里，**默认 `legacy`（即不改现状默认）**。
   - 为什么不是"再加第七套设计语言"：设计语言只换 token 取值与几何（`contract.ts` 的维度开关），
     而这次要动的是**布局结构、设置信息架构、控件形态族**——超出设计语言能表达的范围。
   - 为什么不是"替换旧版"：使用者要"原本的 UI 作为另一套存在"，且替换会烧掉 ADR-0006 的搬运账本。
2. **MD3E 造型以 shadcn/Radix 为基座重皮，不引第二套组件框架。** 保持组件 API、`data-slot` 契约、键盘/读屏行为
   （`DESIGN.md` §Design Contract 已如此规定）。L2 仍走 ADR-0008 的共享出口，主题变量仍由宿主经
   `ctx.theme.overrideTokens` 出一次，节点 UI 不 import `src/backend/**`。
   - 表达性形状用**标准 Web 能力**落地（CSS `clip-path: path()` / SVG / 已在依赖里的 `@material/web@2.5.0`），
     **不从 Rhythm 复制 Compose/Kotlin 组件源码**（见"参考"里的许可）。
3. **控件形状策略是一份"每节点"的持久化偏好，走 settings 面，不落 localStorage-only、不新建配置文件（ADR-0013）。**
   语义：`{ 固定 | 启动随机 }` + 随机时"本次会话抽到的具体形状"。
   - **落点有两个候选，本条先不定死，见"待确认"**：节点业务 `Config`（`xaihi-<node>`）还是界面偏好格
     （`xaihi-core.nodeUi[nodeId]`）。使用者说的是"插件配置"，但控件形状本质是界面偏好，ADR-0013 明确区分这两格。
   - 读写仍经 `NodeSettingsFace`（`packages/ui-host/src/nodes/shared/NodeSettingsFaceContext.tsx:16-37`
     → `backend/nodeSettingsFace.ts:16-30`，桥 `config.getUi`/`config.save`，写带 `expectedRevision`），
     或界面偏好走 `NodeUiConfigStore`（`NodeUiConfigContext.tsx:19-24`）。
   - **随机只在应用启动那一刻发生一次**，结果在会话内稳定；"固定"把当前形状写回同一格。参考项目 Rhythm
     本身是**手动点"Randomize All Shapes"后把具体形状 ID 存成 CUSTOM**（`AppSettings.kt:6949-6979`），
     它**没有**"启动自动重抽"——这一条是 Xaihi 要在其形态基础上**自己补**的行为，不许当成 Rhythm 已实现。
4. **配色与配色风格自由切换，与 MD3E 造型解耦。** 新形态不锁死色板；沿用现有取色（`seedSource: activeTheme` 默认，
   `contract.ts:322`）与自定义主题。切换颜色/风格/明暗只改 token 取值，不改本 ADR 决定的布局与控件形态族。
5. **响应式按容器分档，不按视口。** 新形态的每个节点、顶栏、设置页都读 `useNodeSurface` 的 mode/density 决定
   信息架构降级（侧栏→chips→select、双栏→单栏、异形按钮→更紧凑的形态），窄到 320px 不溢出、不裁文字、可键盘操作。
6. **降级铁律照 ADR-0011 决定 4 生效。** 表达性形状若在某些宿主（官方桌面端 / `dsh web`）下拿不到完整能力，
   必须**探测→退化→退化状态在界面上读得回来**，不许崩、不许静默、不许伪造。

## 与 ADR-0006 的关系（这是本条最容易被误读的地方）

- ADR-0006 管的是**逻辑与真源**：节点核心、动作、CLI/TUI、契约形状——这些**继续搬运，不发明**。
- 本条只把**工作台与各节点的视觉面**划成一处受使用者点名授权的重设计，且是**追加**（旧形态整套保留、可切换），
  不删搬运账本。
- 判据从 ADR-0006 的"保真"变成"**功能保真 + 视觉重设计**"：功能/操作必须逐项等价（能跑同样的动作、同样的快捷键、
  同样的危险确认），视觉/布局/控件形态按 MD3E 重做。**"更好看"这次是使用者明确要的目标，不再是 ADR-0006 里被否掉的理由。**

## 待确认（实现细节，需使用者拍；不拍也能开工但会返工）

1. **形状策略存进哪一格？** `xaihi-<node>` 的 `Config`（业务配置）还是 `xaihi-core.nodeUi[nodeId]`（界面偏好）。
   倾向后者（它本就是 UI 偏好，且 `NodeConfigPopover` 的"开机恢复"开关已经走这一格，
   `packages/ui-host/src/nodes/shared/NodeConfigPopover.tsx:436`），但使用者说的是"插件配置"，需一句确认。
2. **"启动随机"的种子与去重语义**：每次冷启动一个全局种子、各节点派生出稳定形状？还是每节点独立抽？
   同类一致已定，跨节点是否要"看起来成套"未定。
3. **异形形状的可读性下限**：哪些形状在 320px / 高对比 / 读屏下必须回落到胶囊或圆形，需要一条成文规则而不是逐例拍脑袋。
