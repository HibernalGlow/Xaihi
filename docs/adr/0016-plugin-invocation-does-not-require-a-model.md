# 节点/插件的调用不需要模型参与

Xaihi 的节点动作有三条调用面：工作台面板、终端（各包 `bin` 与聚合 CLI）、以及 DSH 的工具执行管线本身
（`ctx.tools.execute()` 是 caller-owned 的入口，计划里第 5 项验收"agent 真实调用该节点注册的 tool 一次"
被读过成"必须让模型跑一次"）。**决定：模型不是调用方的必要条件，从来都不是**——工具只是动作的
*一个*形状，`defineNode` 把每个动作注册成工具时（`packages/node-sdk/src/define-node.ts:273-283`）
其 `execute` 走的就是给面板与命令用的同一个 `invoke()`（同文件 `:221` 的注释明写"命令、面板按钮
这类非模型入口都走它，不要自己再开一条运行"）。所以验收判据落在**非模型入口真跑一次**上，
不再把"要不要花使用者的模型额度"当成一条门槛。

## 为什么这条值得写下来

1. **它推翻了一个反复出现的读法**：从 Step 2 到今天，每一轮交接都把"agent 真调一次 tool"列成
   等使用者点头的事项（`docs/stages/step-2.md` 的 Gate 2.5、`docs/stages/step-3.md:26`、
   `docs/stages/live-remotes-2026-10-07.md` §5 第 1 条）。那三次里模型确实在场，但它是**凑巧的调用方**，
   不是**必需的调用方**——把巧合当判据，结果是一条本可以马上跑的验收被挂在一个需要授权的外部条件上。
2. **不可逆性在于纪律**：一旦"节点能力必须靠模型才够得着"成为默认，就会长出第二套东西去补
   （工具不够就加提示词、提示词不稳就加代理回路），那正对着 ADR-0006 与"不重造 DSH 已提供的东西"。
   钉住"动作先有确定性入口"，这些回路就没有生路。

## 判据（替代旧的那一条）

- **CLI 腿**：`scripts/check-cli-commands.mjs`（承诺的子命令真打得来）+ `scripts/check-cli-parity.mjs`
  （上游开关都在屏上、同参数两次输出一致、`--json` 解析得出结构、**换值后输出必须跟着变**）。
  两条都现跑 rc=0，且各自带阳性对照。
- **面板/命令腿**：非模型入口经 `invoke()` 触发一次真实动作。现状是这条**还没完全通**——
  `packages/ui-host/src/client/node-mount.tsx:229` 对未接的节点运行给出的是**可见拒绝**而不是静默，
  实测注册过的 `ctx.commands` 入口只有两条。所以下一步的验收动作是补命令通道，**不是去跑模型**。
- **`xaihi_nodes` 这个列表面向工具**仍然是真产物，它的判据是宿主 HTTP 面：
  `/xaihi/manifest.json` 的插件数 == `/xaihi/debug.json` 的注册数（`check-remotes-live` 判的就是这个）。

## Consequences

- 之前那三次模型跑的读数（hello / linedup 的工具返回带 nonce 的值）**继续算有效证据**，
  但从"门槛"降级成"额外证"；不再有任何待办以"要不要花使用者的额度"为阻塞理由。
- `CONTEXT.md` 里"命令面"那条原先写"装不下的组合只有 agent 的工具路径能到"，读起来像必须有模型——
  已改成"只有工具执行管线那条路能到（模型不是必要调用方）"。
- 危险闸门仍挂在 `tools/pre-execute` 上（`define-node.ts:286-296`），而 `invoke()` **不走**它。
  这条不因为换了调用方而放松：非模型入口必须自己先问 `dangerFor`，那仍是文件里的原话。
