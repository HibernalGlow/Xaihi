# 赛希（Xaihi）立绘取样与一份外部主题提案的对照

日期：2026-10-09。触发：使用者拿一份外部 AI 生成的「Xiranite · 寂语寒序主题重构」稿，
要求先把角色认准，再谈主题。本文只记**量到的**与**查得到的**，不提实现。

结论先行：

1. 角色**身份**这份稿子说对了；**视觉特征**它仍然没核对原作——三处无出处、一处与原作冲突、
   一处把立绘里真实存在的两个高彩度点整个漏掉。
2. 这份稿子要新建的东西，本仓**已经有了**，而且它要改的那个默认值 ADR-0006 决定 5 已经否过。
3. 赛希主题如果要做，唯一符合本仓法律的落点是 `DESIGN_THEME_ENTRIES` 里**再加一条注册项**，
   照 `lonestar` 的先例（自带出处披露、默认不跟随配色主题），默认语言仍是 `native`。

## 2. 取样方法

脚本：`<repo>/../.scratch/xaihi-art/sample.py`（15 个分数框，非像素硬编码，可复跑）。

```bash
cd <repo>/../.scratch/xaihi-art
UV_DEFAULT_INDEX="https://pypi.tuna.tsinghua.edu.cn/simple" \
  uv run --quiet --with pillow python3 sample.py
```

三条刻意的设计：

- **每框报三个读数**：中位色、4-bit 量化众数、框内**最大 oklch 彩度**像素。只报中位会把
  「青绿发上挂着一颗金胶囊」读成「青绿」，把点缀读丢。
- **彩度窗口 `0.25 ≤ L ≤ 0.95`**。第一版用 HSV 饱和度 `(max-min)/max` 挑「最饱和」，
  于是每个框都被一个近黑像素赢走（`#010000` 的 HSV 饱和度是 1.0）。换成 oklch chroma
  并卡明度带之后，眼睛与胶囊才浮出来。
- **`alpha < 250` 的像素不参与**，避免把抗锯齿边缘当成颜色。
- **不许给 `--md-sys-*` 那类命名空间编短名**：这里的色相/彩度一律现算，不套规范角色名。

## 3. 阳性对照：三个框被自己的图证伪

`sample.py` 会把 15 个框画到缩放副本上输出 `boxes.png`，**必须看图**再采信数值。
第一版看完图判废三处，第二版又判废一处：

| 框 | 第一版落点 | 症状 | 处置 |
| --- | --- | --- | --- |
| `hair_long_left` | 左侧**白色蝴蝶结**与背景 | 众数回 `#D8D8D8`（灰白），不是发色 | 改成 `hair_mass_left` 落在脸左发束 |
| `pearl_beads` | **手背** | 中位 `#CAB1A8` 是肤色 | 挪框后仍是肤色（`#C1B1A7`）：**珠链约 10px，分数框量不到，本表不采信该行** |
| `skin` | 含额头与发际 | 最大彩度读出 `#E1D888` 黄，是发丝高光混进来 | 收窄到 `0.30–0.35 × 0.30–0.35` |
| `background` | 纯白 | 彩度窗口内**一个像素都没有**，`best` 为 `None` 直接把脚本跑崩 | 崩点本身是结论：背景是纯 `#FFFFFF`、零彩度 |

`mesh_dark` 的最大彩度 `#ECE458` 是金胶囊溢进框边，**不算网布自己的颜色**。

三件事只能从表里读出来，从描述里读不出来：

1. **发色是低饱和青绿，不是饱和冰青。** 三块独立区域（刘海 / 发束 / 高光）色相一致落在
   **196–208°**，而彩度只有 **0.021–0.056**。oklch 的绿在 140–160°，所以百科写的
   「墨绿色长发」**不准**；外部稿的「青蓝色」**方向对、程度过头**——按 `#3F9DA8` 那种
   饱和冰青去铺，铺出来的不是她的头发，是任何人都能叫「科技青」的一个色。
2. **全图彩度最高的两处是紫蓝的眼睛（C 0.225 / 0.239）和金色胶囊（C 0.144）**，
   而外部稿的四色板 ICE CYAN / SILVER / PORCELAIN / GRAPHITE **一个都没有**。
   上一版被打回的「紫黄」，恰恰是立绘里真实存在的两笔——那次否掉它和这次提出它，
   错的是同一个动作：都没看图。
3. **背景是纯 `#FFFFFF`、零彩度**，整张图的分层靠明度与金属线，不靠色相。
   这条支持外部稿「中性表面承载信息」的判断——那是它说对的少数几条之一。

## 5. 外部稿的其余特征条目

| 它的说法 | 判定 | 依据 |
| --- | --- | --- |
| 青蓝色长发 | 部分成立 | 色相对（196–208°），饱和度过高（实测 C ≤ 0.056） |
| 黑白服装 | 成立 | 头饰白 `#D0D1D1`／手套黑 `#181818` 众数 |
| 银色头饰 | 成立 | `#BEC0BD` / `#C8C8C8` |
| 角状结构 | 成立 | 左上青绿晶体角，峰值 `#B4FFC2` C 0.111 |
| 褶边袖口 | 成立 | `#B8B8B8` 阴影白 |
| 金属扣件 | 成立 | 与银色头饰同族 |
| 链饰（珠链） | **不背书** | 珠链约 10px，分数框量不到；两次落点都是手背/前臂 |
| 半透明裙装 | **无出处** | 图里有网眼布（`#453F3B`），「半透明裙装」这句在两个 wiki 的正文里都不存在 |
| 哥特式气质 | **无出处** | 同上，是风格判断不是特征 |
| 佩戴面具 | **wiki 正文错** | `warfarin.wiki` 摘要写「身着深色服饰，佩戴面具」，**立绘里没有面具**，她只是把黑色手套的指节抵在嘴前 |

最后一条决定了这条记录的取数口径：**角色视觉特征只能从图量，不能从 prose 抄。**
prose 会同时犯「说错」（面具）和「说得不准」（墨绿）两种错，而且两种都不会自己报警。

## 6. 与这份提案与本仓现实的逐条对照

提案要新建的东西，本仓已经有了；它要改的默认值，已经被否过。

## 7. 赛希主题的正确落点（以及不许做什么）

全仓 `赛希` / `寒序` / `寂语` / `ice cyan` **零命中**。唯一「角色来源」的先例是 `lonestar`：
seed `#F6540E`，值来自一份已落过的校准，**设置面板照实披露「色值不是官方发布的」**，
并且默认 `seedSource: manual` 不跟随配色主题（`registry.ts:65-72` 注释、
`advanced-design-theme-md3.md` §14）。

所以要做，形状只有这一个：

- `src/lib/design-theme/xaihi/{spec.ts,resolve.ts}` ＋ `src/styles/design/xaihi-components.css`，
  命名空间自取（`--xh-*`），注册为 `DESIGN_THEME_ENTRIES` 的又一条，`ownsDimensions: ALL`。
- `spec.ts` 每个值带出处，类别沿用 §12/§13 那套且**不许互相冒充**：本文第 4 节那些
  带框位的取样是 `measured`；按 HCT 从 measured 推 tone 的是 `derived`；
  线宽/间距/控件高度这类「立绘里根本没有」的是 `ui`，且必须自陈「no documented spec value」。
- 面板上照实写：**这些是从一张公版可看的立绘上量的，不是官方公布的色值**；
  并且照 §12 那条教训——复现图不是分光光度计，hex 代表「这张图上的颜色」，
  不许将来拿颜料或设定集给它背书。

**明确不许**（每条都有人已经踩过）：

- 不许翻转默认语言。默认仍是 `native`（ADR-0006 决定 5）。
- 不许把 `--md-sys-*` 那套角色名当活体词表写进任何 CSS；要接管颜色就走 `BRIDGED_COLOR_VARS`。
- 不许写绝对 `font-size`（`advanced-design-theme-md3.md:75` 那条法律；
  ⚠️ 它引用的 `docs/adr/0080-design-languages-scale-fonts-relatively.md` **在仓里不存在**，
  见下节）。
- 不许为了「看起来像终末地」引进任何游戏美术资产、字体或图标。
- 不许拿这份取样当「已经做完主题」的证据：本文只确立**数值出处**，一个 CSS 文件都没写。

## 8. 顺带查出来的两处悬空引用（未修，待使用者定）

`packages/ui-host/docs/advanced-design-theme-md3.md` 引用了两个不存在的决策文件：

| 引用位置 | 目标 | 状态 |
| --- | --- | --- |
| `:75` | `docs/adr/0080-design-languages-scale-fonts-relatively.md` | **不存在**。`docs/adr/` 实际到 `0021`（且无 `0012`） |
| `:86` | `ADR-0069 §Standalone` | **不存在**，同上 |

`:75` 那条不是排版错误那么轻：它把「设计语言不得写绝对 `font-size`」宣布成一条法律，
并据此把 md3 CSS 里的字号声明判为**待改造存量**。于是现状是——
**一条法律宣称自己存在、指向一份没有的文书、并且没有任何尺在守它**，
而 md3 三层 CSS 里仍有 10 处绝对 `font-size`（`md3-components-selection.css:642,650,659,665,686,698,706`、
`md3-settings-nav.css:263,279,287`）。

补 ADR 还是撤掉那句「升级成法律」，是决策不是清理，所以留在这里问，不自己动手。
